# HANDOVER: Whole yeast cell 3D model + WebGPU viewer

This document is for an agent or developer continuing the work on local hardware. Read it fully before changing anything. Facts here were checked against the code and outputs at the time of handover (2026-11-03). Items marked **UNVERIFIED** were not tested.

---

## 0. TL;DR

- **Product.** A structural model of one haploid *S. cerevisiae* cell (BY4741, YPD, log phase) and a browser viewer for it.
  - The model holds 25,213,823 macromolecule instances of 5,483 structure types, packed in 3D at one bead per residue or nucleotide from real PDB / AlphaFold coordinates.
  - The viewer is static-site TypeScript + WebGPU, streams 200 nm tiles, and has cut planes, LOD, picking and Mol* full-atom view.
- **State.**
  - Every pipeline stage runs end to end.
  - The viewer builds and runs with 0 console or WGSL errors in headless Chromium on **SwiftShader (software)**.
  - All 12 guided views render correctly.
  - **Frame rate on a real GPU has never been measured.** This is the first thing to do locally.
  - **Click-picking is broken in the delivered zip.** A depth-texture copy is invalid. A compute-readback fix is in this bundle's `renderer.ts`, but it is untested (§7.8).
- **The whole pipeline is fast.** Geometry about 30 s, packing about 2 min, web encoding about 1.5 min on 16 cores. Regenerating everything from `pipeline/lib` + `pipeline/data` takes about 10 min. Nothing needs to be checkpointed.
- **Three artifacts:**
  1. `yeast_cell_dev_bundle.tar.gz` (this bundle): all source, the structure library and small intermediates.
  2. `yeast_cell_viewer.zip`: built viewer + full encoded web data (546 MB). Use its `data/` folder directly if you don't want to re-encode.
  3. `report_yeast_cell_model.md`, `report_yeast_cell_viewer.md`: scientific write-ups.

### 3.3 Conventions (do not break)
- **Units and origin:** nm; origin at the cell centre. Cell radius `G[0]` = 2156.35; mannan inner `G[1]` = 2121.35; PM `G[2]` = 2046.35; nucleus centre `G[3:6]` = (−990, 160, 90); nucleus radius `G[6]` = 888.7; `G[7:11]` = nucleolus parameters.
- **Rotations:** quaternions stored as (w, x, y, z); world = R·local + p (`pack3d.quat_mat`). In WGSL `qrot` takes q as vec4 (x, y, z, w).
- **Membrane SDF sign:** negative on the lumenal / non-cytoplasmic side. The gradient points to the cytoplasmic (N) side, which is library +z for membrane proteins. For the mito inner membrane the matrix is the N side.
- **Tile key:** `floor(p / 200)` per axis; files are named `{ix}_{iy}_{iz}.bin.gz`; raw npz files are `t_{ix:+03d}_{iy:+03d}_{iz:+03d}.npz`.
- **IDs:**
  - Region ids (24): 0–13 volume regions (cytosol, nucleoplasm, nucleolus, ER_lumen, vacuole, mito_matrix, mito_IMS, golgi_endosome, peroxisome, cell_wall, PM/NE/ER/LD peripheral); 14–21 membranes (PM, ER, NE, VAC, MITO_OM, MITO_IM, GOLGI, PEROX); 22 nucleosome; 23 NPC.
  - Labels (15) and membranes (10) are defined in `cell3d.py`; the same lists are in `web/app/src/data.ts`.
- **Type indices:** the type index = position in `libpack_meta.npz['ids']` = position in `types.json` = what the shaders use.
  - Special types: CCT 570, FAS 1265, NPC 2639, Pma1 3219, PolI 3220, PolII 3221, PolIII 3222, V-ATPase 4577, nucleosome 5479, proteasome_26S 5480, ribosome_80S 5481, tRNA 5482.
  - Re-running packing with a changed inventory changes these indices. `SPECIAL` in `data.ts` is looked up by id string, so update anything hard-coded.

### 4.3 Rendering architecture (per frame)
1. **Clear counters, then compute.**
   - `cullInstances` runs one thread per loaded instance.
     - It applies a visibility class mask and culls against the cut slab and the frustum.
     - It picks LOD by projected bead size (`u.lod.x` px). L0 loops over the type's 64-bead clusters and culls each cluster. L1 uses sphere-tree spheres; L2 uses one sphere at radius `br`.
     - It appends to `list01` (L0 then L1 at offset `capL0`) and `listL2`.
   - `cullSpheres` handles lipid and free-polymer pools.
   - `fin` writes the drawIndirect args.
2. **G-pass** into rgba8 colour + r32uint id + depth32float (reversed Z, compare greater).
   - Draw order: FILL (full-screen analytic SDF section at the cut plane, depth 'always'); organelle/tile meshes; L2, L1, L0 indirect; lipids; free polymers.
   - Impostors are ray-cast spheres with exact depth. The cut plane is applied per pixel, so molecules are sliced.
3. **COMPOSITE:** id-edge outlines (strength fades with px/nm), depth cue behind the cut, selection outline.
4. **Pick:** 1×1 copy of id + depth to a MAP_READ buffer. **Stats:** counter readback roughly every 400 ms.

Further details:
- **Id encoding:** top 2 bits are the category (0 fill/mesh, 1 instance, 2 lipid, 3 free polymer). Free-polymer id = `0xC0000000 | (slot & 0xFFF) << 18 | (kind & 3) << 16 | chain`.
- **Pools** are capped by the adapter's `maxStorageBufferBindingSize`:
  - instances: 8M slots, paged 1024;
  - lipids: 8M;
  - free: 10M, paged 4096;
  - caps capL0 4M clusters, capL1 2M, capL2 8M;
  - at most 4,088 tile slots; uniform 464 B.
- **Render loop:** render-on-demand (`dirty`) and GPU-paced (skips a frame while `onSubmittedWorkDone` is pending). Tile streaming runs on a 150 ms `setInterval`, so it is independent of rAF.
- **Procedural detail** is generated in a worker, CPU-side, only for tiles intersecting the slab with px/nm × 0.55 ≥ 0.8; at most 40 tiles, 3 in flight. It regenerates when the cut plane moves out of the generated range.
  - Lipids: 0.65 nm² per lipid per leaflet; classes PI 20.3, PE 14.9, PC 14.3, PA 8.3, PS 1.8, ergosterol 12, other 28.4%. Removed within 0.95 nm of protein beads (including ghost instances from neighbouring tiles).
  - Glucan: 0.018147 beads/nm³ in the glucan layer.
  - Mannan: 1,908.6 beads per wall protein.

## 5. Web data format (summary; authoritative spec is the `webenc.py` docstring)
- **`library/types.json`:** `{bead_q: 0.005, n_beads: 2470774, n_spheres: 82562, types: [...]}`.
  - Per-type fields: `id, gene, genes, uniprot, name, src (PDB|AF), pdb, oligomer, nb, nnt, bo, so, sn, br, rg, mass, plddt_mean, plddt_frac_kept, copies, regions`.
  - `nb` = all beads, including nucleotides (`nnt` is the nucleotide subset). Bead range is `[bo, bo + nb)`; sphere-tree range is `[so, so + sn)`.
- **`library/beads.bin`:** 8 B per bead: int16 xyz × 0.005 nm, u8 kind (0 protein, 1 nucleotide), u8 pLDDT (255 = experimental). **`library/spheretree.bin`:** f32 xyzr.
- **`tiles/{ix}_{iy}_{iz}.bin.gz`:** "YCT1" binary.
  - Header: 16 × u32.
  - Instances: 16 B each: type 14 bits, quaternion largest-index 2 bits, region 5 bits, flags; position u16 × 3 at `lo − 80 + u·360/65535`; quaternion smallest-three int16.
  - Ghosts: near-membrane instances of neighbouring tiles, same encoding relative to this tile's `lo`, used only for lipid masking.
  - Polylines for mRNA (0.005 nm) and linker DNA (0.01 nm): u32 lengths, i32 starts, i8 deltas.
  - Membrane mesh: u16 vertices, u16/u32 triangles, u8 membrane id per face.
- **`tiles/index.json`:** `tile_columns` + `tiles` rows (`ix, iy, iz, n_inst, n_ghost, n_mrna_beads, n_link_beads, n_vert, n_tri, gz_bytes, label_mask, vol_glucan_nm3, vol_mannan_nm3`), plus `region_names`, `label_names`, `mem_names` and `wall` constants.
- **`types_tiles.bin`:** u32 `off[NT + 1]`, then u16 tile indices (tiles containing each type; used for fly-to-nearest).
- **`geometry.json`:** `G[11]`, `pores` (117 × 3), primitives `PT/PQ/PC`, `consts`, uniform `grid` (32³ over ±2200 nm) with `prim_off/prim_idx/pore_off/pore_idx`, label/membrane names, `npc_pos`, `mito_segments`. The WGSL SDF reads this directly.
- **`organelle_meshes.bin.gz`:** u32 count, then (mem, nV, nT) × count, then per mesh f32 vertices and u32 triangles.
- **`bookmarks.json`:** `[{name, caption, target, normal, up, width, slab}]` × 12.
- Total: 6,416 tiles, 516 MB gz (raw 603 MB); largest tile 0.34 MB gz.

## 7. Known issues and bugs
1. **Real-GPU performance is unknown (highest priority).** Likely hot spots:
   - (a) `cullInstances` loops serially over all clusters of a type in one thread. The NPC has about 3,400 clusters and the ribosome about 260, which causes heavy divergence. Consider a two-level dispatch: instance pass emits (instance, cluster-range) work items, then a cluster pass.
   - (b) The FILL pass evaluates the analytic SDF per pixel through the primitive grid.
   - (c) Lipid and mannan counts at close range: mannan density is about 0.235 beads/nm³, up to about 1.9 M per tile.
   - (d) No Hi-Z occlusion culling (it was optional in the plan and is not implemented).

   Use Chrome's WebGPU timestamp queries (`timestamp-query` feature) to profile per pass.
2. **Validation JSON mislabel.** `wholecell3d_validation.json` has `"mrna_threads": 28758168`, but that is the **mRNA bead** count. There are 30,000 threads (`index`/stage-2 output `n_mrna = 30000`). Fix in the cell-31 code.
3. **Pool overflow.** Counters are clamped to caps in `fin`, so excess items are silently dropped. The HUD shows "memory budget reached" only for instance-page starvation. There is no warning for list-cap or lipid/free pool overflow.
4. **Procedural detail is CPU-side in workers**, not GPU compute as the plan said. There is visible latency when the slab moves fast or with very thick slabs. A port to a compute shader with deterministic hashing is possible; the worker code is the reference.
5. **Hard-coded paths** in Python (§2), and orchestration lives only in notebook cells (§3.2).
6. **TypeScript:** 6 benign `GPUAllowSharedBufferSource` type errors (strict ArrayBuffer generics). Fix with `as BufferSource` casts or typed `new Float32Array(new ArrayBuffer(..))`.
7. **The "fps" HUD reads 0 on SwiftShader.** The frame-time average is only fed while frames are continuous. It is fine on real GPUs but **UNVERIFIED**.
8. **Picking was broken in the delivered zip; a patch exists but is UNTESTED.**
   - Symptom (headless test, `?view=4`): `yc.pickAt(640,400)` returned `{id:0, depth:0}` ("Outside the cell") and the click did not open the inspect panel. The WebGPU log said: `copyTextureToBuffer` of a 1×1 region of the `depth32float` texture is invalid, because depth/stencil textures must be copied whole. That invalidated the whole frame's command buffer.
   - Patch (in this bundle's `web/app/src/renderer.ts`, **not** in `yeast_cell_viewer.zip`): a 1-thread compute pass (`pickPipe`) does `textureLoad`s on the id and depth textures at the pixel, writes them to `pickOut` (16 B storage), then `copyBufferToBuffer` → `pickBuf`. The readback now takes id = u32[0] and depth = f32[1].
   - It compiles (`vite build` is OK), but was not run: the test was stopped. **First task: verify on a real GPU.** Check that click → the inspect panel shows a protein, that a double-click flies to the picked depth, and that there are no WebGPU validation errors. Then rebuild and re-zip with `web/package.sh`.
   - Check whether `depthTex` needs `TEXTURE_BINDING` usage. It already has it (renderer.ts `resize`).
   - `yc.describe(id)` and `yc.setType(i)` work: TDH3 is type 4232, with 248,633 copies.
9. **UNVERIFIED UI paths.** Tested headless: boot, all bookmarks, quality presets, `?view=` deep links, and the preview page. Not exercised:
   - Mol* modal (needs network to RCSB / AFDB; CORS was checked earlier). It depends on picking, so test it after item 8.
   - tour, sweep, minimap click, organelle mode rendering;
   - screenshot button, keyboard flight, search-box UI, the help/about modals as interactions;
   - Safari and Firefox.
10. **Results-panel preview.** `yeast_column_preview.html` (13 MB) may not get WebGPU inside an iframe; it is untested there.
11. **Data size** is 546 MB zipped. Options to reduce it:

## 9. Scientific caveats and improvement backlog
**Scientific accuracy** (from the last user discussion):
- **Total protein count is likely low.** The model has 4.2e7 molecules in 42 µm³ = 1.0e6 per µm³. Published normalised estimates give 1–3e6 per µm³ for yeast (Dolgalev et al. 2023, IJMS, doi:10.3390/ijms24032081). The user was offered a rescale to a mass-based total and repack.
- **Ribosomes:** 167,339 placed, against a growth-law estimate of about 3 × 10⁵ in YPD (Kostinski & Reuveni 2021, Phys Rev Research, doi:10.1103/physrevresearch.3.013020).
- **Organelle volume fractions vs serial-section EM** (Yamaguchi et al. 2011, Microscopy, doi:10.1093/jmicro/dfr052: nucleus 10.5%, wall ~17%, vacuole 5.8%, mito 1.7%). The model has nucleus ~7%, wall + PM ~14%, vacuole 7%, mito 2%; the nucleus is small.
- **Mitochondria are under-filled** because of RSA saturation. Possible fixes: larger mito volume, multi-pass packing with small-first back-fill, or a denser packing algorithm.
- **Localization:** 625 proteins defaulted to cytosol (no UniProt or GO localization). Candidate fix: a GFP-localization atlas (e.g. CYCLoPs / YeastGFP).
- **Missing components:** cytoskeleton (actin patches and cables, microtubules; a tubulin dimer exists in the inventory), FG mesh in the NPC, rDNA / nucleolar organisation, metabolites. AF pLDDT < 50 trimming removes disordered volume; quantify it per compartment.
- **Copy numbers** come from the PaxDb integrated whole-organism set, not BY4741/YPD-specific; uncertainty is about 2-fold.

**Engineering backlog**, suggested order:
1. Measure fps on a real GPU and profile per pass (§7.1).
2. Make paths configurable and port the notebook orchestration to scripts plus a `make all`.
3. Two-level cluster culling, and optionally Hi-Z occlusion.
4. Overflow warnings in the HUD; adaptive caps.
5. Functional UI tests (Mol*, tour, organelle mode, search) in headed Chrome.
6. Data size reduction (§7.10).
7. Scientific rescale (total proteins, ribosomes, nucleus size), then re-run packing → validation → encoding → package. About 10 min of compute.

## 10. Regenerating everything after a model change
```text
inventory/ingredients (cells 1–8, 22)  ->  cell3d.build (24)  ->  tiles3d.run_geometry (25)
 -> wc3d.expected_totals / build_libpack / distribute / prepass (27–28)  ->  run_phase x 8 (29)
 -> validation (31–36, writes libpack_meta.npz)  ->  webenc stage1 / encode_library / linker / stage2 / index / meshes / bookmarks (38–44)
 -> web/app: npx vite build  ->  web/build_preview.py  ->  web/package.sh  ->  test_viewer.py bookmarks
```
- Bookmarks (cell 44) are hand-placed coordinates tied to the current geometry (seed 11). If the geometry changes, re-target them; the NPC bookmark uses the NPC nearest the cell surface.
- `build_preview.py` has a hard-coded tile block (ix −11…−8, iy 0–1, iz 0–1) and NPC position (−1856, 250, 122), which are also geometry-specific.
